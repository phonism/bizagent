# 用户指南

[文档导航](README.md) · 尚未安装？先看[快速开始](quickstart.zh-CN.md)。

只用个人记忆，可从[存下一条规则](quickstart.zh-CN.md#第一次成功存下一条规则)开始。
想试团队协作，直接做下面的虚构订单练习；已有组织和未建组织的环境都可用。

## 入口与状态速查

| 你要做什么 | 从哪里进入 | 看什么 |
| --- | --- | --- |
| 确认当前 Agent 属于谁 | 会话顶部的 Home 按钮 | Home 名称，以及日常/主/项目/工作会话类型 |
| 查规则是否保存 | Home 按钮 → 学习 | 资产正文、证据来源、active/candidate 状态 |
| 查派工和交付 | 会话的「工作与经验」页签 | 工作状态、结果正文、产物、查看执行会话 |
| 从 Worker 回到负责人 | 工作与经验 → 返回派工会话 | 原来的派工会话 |
| 找项目并人工验收 | 工作与经验 → 项目；或 BizAgent → 项目 → 我的审核待办 | 当前提交、证据、验收或返工理由 |
| 回信给 Agent | 会话顶部或 BizAgent 中的「我的收件箱」 | 回复内容、发送回复、标记已处理 |
| 查这一轮产生了什么 | 回答下方的「本轮留下…项记录」 | 该轮成功保存的经验、工作和项目记录 |

空白新会话需要先发送消息，才会出现完整的会话入口。学习页点击「对话」会重开该 Home 的长期主会话；
新项目有自己的项目主会话，正式 Work 在另一段执行会话中完成。

三种状态分别回答不同问题：

- **运行中 / 空闲 / 未加载**：DSH Agent 当前是否正在执行；未加载本身不表示失败。
- **待接单 / 已接单 / 已完成**：正式 Work 的进度；完成后展开结果检查交付内容。
- **推进中 / 待验收 / 已验收**：Project 的交付与审核进度；页面验收后为 `accepted`，项目详情也可能显示「已通过」。

回执中的「记录时」描述历史，当前状态以工作卡片或项目详情为准。「工作与经验」只列当前会话派出或承接的工作；
项目列表也受当前 Home 的参与权限影响。找不到时返回负责人/项目会话，或查看自己的审核待办。

## 完成一次协作练习

### 1. 准备两个练习 Home

在 **BizAgent 组织 → 学习 → 创建 Home** 分别填写：

| 字段 | 负责人 | 分析师 |
| --- | --- | --- |
| Home 类型 | Personal | Personal |
| 唯一标识 | `practice-lead` | `practice-analyst` |
| 显示名称 | 练习负责人 | 练习分析师 |
| 初始 Identity | 负责上手练习项目的派工、复核和提交，只处理练习数据。 | 承接上手练习的正式 Work，独立核对订单，交付报告和计算日志。 |

将生成 `personal:practice-lead` 和 `personal:practice-analyst`。编号已存在时换用新编号，并同步替换后面的提示语。
已有组织时练习 Home 创建在当前组织空间；`Personal` 表示成员类型，和外部的「我的个人 Home」分开。
当前本机用户拥有新建的两个 Home，满足自动派工的同 owner 条件。

**检查**：学习页能分别选择两个 Home。选择负责人，点「对话」，确认会话顶部显示「练习负责人」。

### 2. 教负责人一条规则

在负责人的主会话发送：

> 记住这条仅用于上手练习的规则：订单 GMV 只计 paid，排除 cancelled 和 refunded。
> 请实际保存到当前 Home，告诉我资产编号和状态。本轮只保存规则。

**检查**：从 Home 按钮进入学习页，展开资产，核对正文、来源和 `active` 状态。
如果是候选，先核对依据再请 Agent 发布，不要把候选当成已生效规则。

### 3. 创建项目，再进入项目对话

回到负责人的主会话发送：

> 创建 BizAgent 项目「上手练习：订单 GMV 核对」。目标是让练习分析师独立核对四笔虚构订单。
> 完成标准：正式 Work 在分析师自己的会话接单并完成，交付逐笔报告和计算日志，负责人复核后提交给我人工验收。
> 本轮只创建项目，订单稍后在项目对话提供。

**检查**：在「工作与经验」的项目栏点这个项目，再点「打开项目对话」。
会话顶部应显示「项目主会话」及项目名称，和刚才的 Agent 主会话分开。

### 4. 在项目对话派工

发送：

> 先读取当前 Home 保存的上手练习 GMV 规则。订单是 A：paid 100 元，B：paid 200 元，
> C：cancelled 50 元，D：refunded 30 元。请关联当前项目，向 personal:practice-analyst 派正式 Work。
> 请分析师在独立会话接单并核对，将逐笔报告和计算日志保存到 artifacts/ 并随结果交付。
> 结果返回后请复核产物，提交给我人工验收。

**检查**：「工作与经验」出现负责人 → 分析师的工作卡片。用「查看执行会话」核对分析师的 Home 和接单记录，
再用「返回派工会话」回到项目。结果会自动回传；交付前不要重复派同一个任务。

### 5. 看结果，然后亲自验收

正确结果为 **300 元**：A、B 计入，C、D 排除。展开 Work 的结果检查逐笔说明和产物。

负责人提交后，从项目卡片进入详情：查看当前交付与「下载提交版本」，填写「验收或返工理由」，
点击「验收通过」；不满足标准时点击「退回返工」。也可从「我的审核待办」查找待验收结果。

**成功标志**：Work 为「已完成」，Project 为「已验收」，结果和已下载的提交版本一致。
若退回返工，负责人需修订并重新提交，你审核的是新版本。

### 6. 可选：验证收件箱回信

在项目对话发送：

> 读取当前 Home 的 owner，向对应的用户地址（user: 后接实际 owner）发一封普通 Inbox 信件，标题为「上手练习：核对完成」，
> 简短告知结果与项目状态，然后结束本轮。

打开「我的收件箱」，回复“收到，请确认这条回复，不再派工或修改记忆”，并标记原信已处理。

**检查**：回到原项目会话，它自动接收到你的回复并确认。发信/已处理记录与 Work、Project 的状态各自保存。

## 该用哪种协作方式

| 你的目的 | 用什么 | 行为边界 |
| --- | --- | --- |
| 当前对话参考另一个 Home 的知识 | `@` 选择共享 Home / Frame | 在同一会话加入只读上下文，检查输入区 Frame 状态 |
| 给另一个 Agent 留信或提问 | Inbox | 对方在自己的会话读取、回复；送达和已处理各有记录 |
| 让对方负责一份明确交付 | 正式 Work | 约定目标和验收标准，在独立工作会话接单、完成 |
| 围绕长期目标组织交付并由人确认 | Project | 关联 Work，汇总证据，提交后由人验收 |
| 把经验保存到另一个 Home | Proposal | 目标方主人接受后才进入目标 Home |

`@` 候选提供 Business、Role、Capability 共享 Home，不列出其他 Personal 成员 Home。
输入 `@`，从带 Home 地址的候选中选中再发送；在输入区查看加载状态，失败时先处理加载提示。
给分析师派工时直接使用它的地址即可，无需先 `@` 它。
Frame 条目上的「主导」「协作」描述上下文角色，独立执行要看正式 Work 及执行会话。
